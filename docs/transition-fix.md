# 0.3.1 卡片转场停在中间：定位与修复

历史专题：0.5.1 已改用原生 swiper，本文中的 JS 双卡、CARD_REST 和独立收尾不是当前设备导航。保留原生终态与故障注入经验；当前架构见 [技术方案](robot-technical-plan.md)。

2026-09-20。用户反馈 0.3.0 真机滑动切屏停在中间，页面不能完整显示。

## 已定位的应用缺陷

`index.ux` 的转场结束和取消都执行 `cardStyle = ''`。这只清空绑定字符串，没有向 Vela 原生控件写入最终位置和透明度；原生控件会保留上一次收到的 `left/top/opacity`。

正常每 40ms 回调时，最后一帧已经接近终点，所以旧检查容易漏掉。设备繁忙导致跨过结束时刻时，最后一次写入可能仍是中途位置，随后只清空字符串，偏移或透明状态便留下来。旧实现也只有一个逐帧回调链，没有独立的到期归位。

这是本次复现和修复的应用层问题；没有测得用户固件上的具体调度延迟，不能把延迟来源归为某个已确认的固件故障。

## 对照复现

只在本地模拟器探针包中，把进入阶段的下一次帧回调延后 650ms，模拟帧未按时执行；未向手环安装探针。

| 版本 | 结束处理 | 原生模拟器结果 |
| --- | --- | --- |
| 0.3.0 探针 | 清空样式字符串 | 进入帧的透明状态被保留，结束后仍不可见 |
| 0.3.1 探针 | 明确写 left=0、top=0、opacity=1，并独立收尾 | 时钟完整显示、位置正确 |

证据 `.artifacts/v030-delayed-card-8.png`、`v030-delayed-card-settled.png` 与 `.artifacts/v031-delayed-card-8.png`。镜像为 PRE 4.0、192×490，不是手环 OS 3.1.32。正式包移除了 650ms 延迟注入。

新测试在旧源码上先失败，涉及空的最终样式、前后台中途取消未归位、逐帧回调丢失后仍为 left=110/opacity=0；记录在 `.artifacts/v030-transition-regression.log`。这弥补了旧测试只检查 JS 页面名称和转场标记、未检查最终原生属性的缺口。

## 修复

- `CARD_REST` 明确写入 `left:0px;top:0px;opacity:1;`，初始化、完成、取消、hide/show 均使用它。
- 统一收尾时同步目标页与显示页；新手势打断旧转场时先归位，同目标请求直接收尾。
- 420ms 独立完成回调，不依赖逐帧链执行到最后；常规刷新和下一次输入还会检查过期转场。
- 使用会话代号忽略旧回调，退出／后台同时清理逐帧任务和完成任务。
- 保留原有 420ms 方向滑动与淡入淡出；没有改动眼睛资源、图标、名称和常亮策略。

23 项测试通过，覆盖四方向延迟最终帧、快速换页、前后台打断、同目标返回、回调丢失后恢复，以及原有手势、常亮和退出约束。安装和真机反馈状态见 `handoff.md`、`validation.md`。
