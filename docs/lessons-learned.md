# 开发经验与排障手册

整理于 2026-09-20，基于用户反馈、当前代码和本机验证记录。阅读当前状态请先看 [handoff.md](handoff.md)，不要从历史案例推断新版本已经通过真机验收。

## 最重要的经验

**浏览器好看、逻辑测试通过、模拟器能动、设备安装成功，是四件不同的事。** 本项目多次在模拟器检查通过后收到真机失败反馈。涉及性能、弧边、触摸派发、局部重绘、常亮时长，最终必须收设备反馈；收到反例要改状态记录，不能用先前截图反驳。

排查时将结论分成四类：用户实测现象、代码能证明的缺陷、模拟器对照复现、仍未证实的解释。例如黑线在移除旋转父层后获用户确认消失，但“具体固件重绘机制是什么”依然未知。

## 性能定位顺序

1. 先标明版本、设备／模拟器和操作阶段：按下、移动、松手、动画结束、状态返回，避免将整段延迟都叫“帧率低”。
2. 区分输入晚到、JS 忙、创建／解码资源、属性传递、原生重绘。当前尚未取得真机分阶段耗时，不能凭现象给各项分摊时间。
3. 做最小对照：暂停眼睛、预备目标页面、减少动态属性、固定尺寸、只改变值图。保留失败前后的证据和唯一差异。
4. 拖动必须在**手指还没松开时**取帧。只比较松手后的两张整页图不能证明跟手。
5. 检查取消、中断、事件丢失、前后台和结束回调晚到。短拖回弹后应恢复同一页；不要只断言 JS 里的 view 名字正确。
6. 真实手感最终依赖用户实测或真机时序采集；模拟器机器快慢和截图频率不能换算为手环 FPS。

## 视觉回归方法

截图使用同一页面、时间／状态基线，先排除预期时钟变化，再做 RGB 差分。对按钮更新，可限定允许变化的物理区域：0.5.1 的值图为 x=50..89、y=59..218；16 帧探针差异都在该区域，卡片轮廓保持不变。这个结论仅证明对应模拟器探针，不直接证明手环无闪烁。

对于弧边，要检查可见字形和圆角轮廓是否在真实胶囊内，不能仅证明矩形在 192×490 中。用户允许内容铺满屏幕不意味着矩形四角可用。图片区和点击区要同时验证；两者各自看似合理，合起来也可能错位。

UI 规格和资源规格不同要显式处理：静态控件尽量按原尺寸显示，避免状态切换重新布局／缩放；不要默认网页 CSS 的所有值和“清空属性”语义都被 Vela 实现。

## 探针与证据边界

故障注入或模拟成功回调只能用于专用模拟器。先保存基线，记录注入内容、生成包及截图，再还原正式源码、使用真实接口测试和构建。最终包的日期必须来自系统，常亮必须调用真实 API。不得将固定日期／成功回调探针上传手环，也不能以它证明实际常亮。

截图和日志命名带版本与目的，例如 `v051-probe-30-*` 和 `v051-clock-after-cancel`。记录本机路径、结果与限制；`.artifacts/` 不会自动随 Git 交接。必要证据可整理为可分享材料，但先排除凭据和设备标识数据。

## 产品与数据经验

- 白色要求针对眼睛，不能扩展成全应用单色；大字和低密度比添加解释小字更适合手环。
- 用户最新要求覆盖旧设计：去掉中央安全矩形、允许指定情绪轻微位移、移除设置标题与翻转、节日／休班统一底栏。
- 节日当天与放假区间不同。只有核对过的当年官方数据才能标休／班；普通周末不是自动的官方休假标记；新年不能复制上一年调休。
- 系统心率／血氧监测和应用自己的订阅不是一回事。不订阅只说明本应用未主动采样，不等于系统停测或功耗已经降低。
- 开源“参考概念”与“复制资源／代码”必须分别记录。保留真实上游许可，不能拿第三方移植版的宽松标注覆盖原作者许可。

## 交接时最容易漏的事

保留包名和本地签名；明确“源码修改／构建／已安装／真机确认”四种状态；将用户新增的失败反馈补到验证流水和当前交接；不要为了核验文档重新安装设备。当前待验收版本以 handoff 为准；长期常亮、到期释放和持续底座展示须专项观察。

## 0.6.0 静止调度边界

仅按 `Math.floor(elapsed / (1000/60))` 去重会遇到浮点帧号重叠：`owo` 4234ms 与 4250ms 曾落在相同帧号。后一时刻恰好是睁眼终态，如果跳过采样再进入 1 秒静止等待，会让最后 1px 不透明眼睑停留。现行规则是在长等待前应用终态，仍只写发生变化的属性。集成回归先复现失败再通过，并覆盖 hide/show 对静止回调的隔离；这是代码缺陷证据，不应扩写成已证实的固件黑线原因。

## 0.8.2 小屏文字与原生证据

用户否定 v17 的颜色、字号、套餐与对齐。新版先收敛白／灰／绿层级，再用整行自然字距的预旋转 PNG，避免英文逐字符定宽拼接；所有动态倒计时必须有资源覆盖。环内窗口文字须透明，黑底矩形会遮住下缘圆环。素材改名避免旧尺寸混淆，但不能据此宣称已定位真机缓存问题。

整行资源增加 RPK 大小，PRE 工具包默认 10 秒解压超时。脚本只对专用模拟器使用 120 秒解压，不触碰实体手机。原生截图视觉若与预期冲突，复核保存文件的 RGB 像素和哈希；v18 持按、释放 5 帧及静止 8 帧与基线 RGB 完全相同，不能把展示工具偶发显示黑图直接当作设备黑屏证据。
