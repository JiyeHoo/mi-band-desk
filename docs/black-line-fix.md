# 0.4.1 页面更新黑线修复

2026-09-20。设备 Band 9 NFC / M2346B1 / OS 3.1.32。安装状态见 handoff.md。

最新反馈：用户在 0.4.1 安装后确认“现在没有黑线了”，本次兼容修复的真机结果通过。以下保留定位过程及当时的验证边界。

适用范围：继续保留物理坐标、预旋转图片和整数眼睑；文中独立输入层、整卡状态替换及 JS 转场已被 0.5.1 原生分页和局部值图替代。以下是历史修复记录，当前架构见 [技术方案](robot-technical-plan.md)。

## 现象与定位边界

用户先报告表情动画之后屏幕中间有黑线，随后补充：首次进入页面没有；动画更新后出现；设置页常亮时长按钮首次正常，点击更新后按钮内部也有黑线。这说明不能只修眼睛动画。

源码中的共同路径是：0.4.0 把 490×192 显示层整体旋转成物理 192×490，眼睑、设置文字等子节点在旋转父层中局部刷新。首次完整绘制正常、局部更新异常与这条路径相符。因此将“旋转父层的局部重绘兼容问题”作为修复假设；没有真机渲染日志／固件源码证明具体失效机制。

本地 PRE 4.0 连续眼睛截图 `.artifacts/blackline-v040-baseline-*.png`、设置按钮更新前后截图未复现持续黑线。旧按钮同为“失败”状态时，两个截图有 344 个轻微颜色差异像素，不能把它们当成黑线证据。模拟器和真机 OS 不同，也不能用未复现否认用户反馈。

## 实施

- 删除整个页面的运行时 transform，包括 stage。所有页面直接在物理 192×490 坐标上布局，仍使用禁滚动根 scroll 和独立输入 scroll。
- 图形、固定文案和按钮在生成资源时旋转。两个方向共 170 张 PNG，85 组图片的 180° 像素对应关系已校验。普通绘制只改变原生位置、尺寸、图片源和透明度。
- 时钟／日期／七天日历由预旋转字形拼接，保持原大字号及配色；设置每种常亮状态使用完整卡片位图。没有加入统一中央安全区。
- 眼睑只用整数像素，打开时采用非零占位尺寸＋opacity=0，不依赖 height=0 的裁剪。上下边界按同一个取整后的厚度生成，防止一像素接缝。
- 转场位移映射到物理坐标，保留 CARD_REST、独立完成任务、超时恢复和旧回调隔离。横屏逻辑方向与实际手势对应不变。
- scripts/verify-package.mjs 禁止设备模板重新引入 transform／animation-name，并逐张校验所有预旋转资源的尺寸和源／包字节一致性。

实现文件：src/pages/index/index.ux、src/common/{layout,animation,physical-ui,physical-glyphs}.js、scripts/{physical-assets,generate-physical}.mjs。PNG 内容来自现有原创眼形和本机字体绘制；无新增在线素材或运行时 Web 页面。

## 验证及限制

31/31 逻辑测试和实际 RPK 编译校验通过。新增测试覆盖两方向显示／点击坐标一致、全部情绪的非零眼睑和睁开清理、物理转场方向、常亮整卡状态图片，以及分钟／日期文字变化和中断切页。

PRE 4.0 原生检查包括连续表情、时钟与七天日历、设置更新、两种方向四向拖动、翻转后的按钮点击、左右弧形端部取消／确认、快速多次切页和最终退出。v041-menu-before／after 在同一“失败”状态下像素完全一致。模拟器的常亮模块不可用，成功的 30 分／2 小时状态用逻辑测试检查，不能当作真机常亮验证。

最终包再次检查连续表情、连续八次常亮点击以及快速进入日历的完整归位。截图命名为 .artifacts/v041-final-*.png，事件记录保存在 .artifacts/emulator.log。未使用故障注入包进行部署。

当时的真机复测清单（后来用户已确认黑线消失）：从入口重新打开，观察眨眼／流泪／比心后是否再有线；进入设置连续改变常亮时长，检查字和按钮底色；翻转后重复，并快速切换页面。必须得到实际设备结果后才能标记“黑线消失”。本轮没有推断硬件损坏，也没有确证固件内部根因。
