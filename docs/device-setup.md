# 设备连接与部署边界

本文描述本项目开发环境中使用 AstroBox 安装和检查的方式，不是唯一的连接或配对方案。其他选择可参考 [xiaomi-band9-mcp](https://github.com/Soodok/xiaomi-band9-mcp) 与 [米坛社区](https://www.bandbbs.cn/)。

最近确认的设备安装为 **0.9.2 / v21**；设备、插件及验收的最新状态见 [handoff.md](handoff.md)。下文有关原绑定手机、目标核验和安装脚本的约束适用于本项目的开发设备。

## 已有环境

本项目通过 AstroBox 的本地 CLI／接口提交 RPK。手环绑定另一台 Android，与 Mac 上可能出现的 ADB 手机无关。专用 Vela 模拟器与实际手环是两条独立验证路径。

已有连接正常时，直接核对目标和队列，不重新执行配对、账号导入或“连接新手机”。断连时优先在 AstroBox 中对已保存的同一目标恢复连接，再核对型号。若无法恢复，说明具体状态，由用户处理需要在手环或原绑定手机完成的操作；本项目不能擅自解绑、恢复出厂、清理 NFC／支付数据或操纵原手机。

历史首次接入曾遇到 macOS 校验和手环连接准备，由用户完成。归档过程不再作为重复执行步骤。新环境的登录、验证码等由用户输入，不要求其将密码或 AuthKey 发给代理，也不绕过系统安全提示。

## 升级流程

1. 按 [开发指南](development-guide.md) 构建和检查实际 RPK。
2. AstroBox 核对唯一连接目标名称、型号 M2346B1、固件，以及本项目应用包名是否存在／版本。安装脚本只自动核对数量和名称，不能替代型号检查。
3. 查看下载／安装队列，等待已有任务有明确结果后再操作。
4. 让手环停留在表盘并保持亮屏。需要排除插件流量时，退出 AstroBox 后临时移出插件目录，再重启并连接同一保存目标；结束后必须原样恢复插件。
5. 执行 `npm run device:install` 一次。
6. 如果 CLI 等待超时，先查队列；随后重新进入设备信息 → 快应用，确认包名和新 versionCode。不要因超时重复安装。队列清空但设备版本未变化属于失败。
7. 从手环入口打开“机器人桌搭”，进行本轮真机复测，记录结果而非预先标记通过。

```sh
npm run device:status
node_modules/.bin/astrobox-cli queue status
npm run device:install
```

`npm run deploy` 会构建并安装；不能把它当作只读验证命令。保留 `sign/` 中同一签名身份；项目文档可分享，签名私钥和账号凭据不能随文档提交。

## 当前真机检查入口

先从手环入口打开“机器人桌搭”，目视确认黑底白眼首屏不是纯黑；不要把列表版本当作 UI 通过证据。随后按 [验收清单](release-checklist.md) 检查四页循环、Codex 额度页、双击刷新、设置和返回系统。若出现异常，先退出应用并记录现象，不立即重复安装。

充电动画可能短暂覆盖，用户曾确认结束后应用继续显示；这不是长期底座展示已通过。长期常亮与功耗、0.6.0 动画、滑动和设置更新体验仍须按 [验收清单](release-checklist.md) 收集反馈。

连接能力来源：[AstroBox 官方连接说明](https://abox.run/docs/usage/connection)。历史原文见 [首次连接归档](history/device-setup-initial.md)，其中已过时的版本／按钮和配对步骤不得作为当前操作指引。
