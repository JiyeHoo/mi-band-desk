# 验证与交付清单

先读 [handoff.md](handoff.md) 的当前版本和待验收项。本清单用于选取相关检查，不要求每次文字修改都重跑全部程序或安装。

## 按改动选检查

| 改动类型 | 必要检查 | 不能由它证明的事 |
| --- | --- | --- |
| 仅文档／记忆 | 链接、事实、版本与当前源码／记录一致；敏感数据检查 | 新的设备行为 |
| 手势／生命周期／常亮 | npm test、构建、相应原生操作；必要时用户真机复测 | 单元测试不模拟原生事件和真实亮屏 |
| 字体／按钮／布局 | 生成素材、RPK 尺寸校验、真实更新过程和点击／弧边截图 | 矩形在屏内不代表字形与轮廓在弧线内 |
| 动画／性能 | 连续帧、拖动持按帧、取消与中断、相关调度测试、真机体验 | JS 更新率不等于屏幕 FPS |
| 年份假期 | 官方通知核对、节日与假期区分、调休／跨年测试、底栏展示 | 未收录年份不能推断安排 |
| 名称／图标 | npm run icons、manifest／入口图一致、真机启动器 | AstroBox 列表名称不能证明实际启动器布局 |
| Codex／Mac 连接 | App Server 结构探针、Mac HTTP、插件 WASM 构建、协议测试、真实 ACK | 任一单段通过都不等于 Mac→手环闭环 |

## 构建与原生检查

```sh
npm test
npm run build
npm run emulator
```

- [ ] 相关逻辑测试通过，构建后的实际 RPK 校验通过；版本与源文件新鲜度正确。
- [ ] manifest、入口图、资源字节与尺寸、CRC、许可／署名、私钥排除检查通过。
- [ ] 若使用探针，记录注入内容，恢复正式源码和真实 API／系统日期后再构建交付包。
- [ ] 手势改动检查左／右桌面、上进设置／下返回、短拖取消、快速连续操作、手指未松开的画面。
- [ ] 点击改动检查刚打开直接点、抖动、小拖、取消、拖动后再点；一次拖动不能触发退出或常亮。
- [ ] 系统返回保留应用；左叉取消；右勾显式确认后有 destroy／App Closed 证据。
- [ ] 常亮检查成功／失败／pending／关闭等状态。模拟器接口不可用时，不能把失败→失败当成成功状态刷新；必要探针仅用于模拟器。
- [ ] 显示改动检查静态图和更新过程。退出后关闭本项目模拟器。
- [ ] 自动切换默认开启；关闭后手动分页可用、重启保留关闭；再开启重新计时。状态只更新小图，拖动不能误触。
- [ ] 轮播检查 60／10／10／10 实际原生循环、滑动中间帧、手动打断、持按／取消、设置暂停、后台重进和缺失回调；不用只改 JS index 的测试冒充动画验证。
- [ ] Codex 卡片检查无数据／缓存／新鲜／断连／过期、0%／1%／59%／100%、已知／未知套餐、刷新失败和重复／倒序 revision。
- [ ] macOS 产物验证签名、arm64 启动、只监听 127.0.0.1；快照不得出现登录令牌、邮件或凭据字段。
- [ ] AstroBox 插件单独记录“已构建／已导入／已转发／已 ACK”；导入前核对权限和目标，不能用编译成功代替运行结果。

当前 UI 只有默认横屏，反向坐标做逻辑回归即可；如果以后重新引入翻转，需要重做两个方向的原生四向和点击检查。

### 专用模拟器操作示例

在 `npm run emulator` 启动的终端中逐条输入；坐标为物理坐标。先确认所在页面再操作，不把依赖步骤并行发送。

```json
{"swipe":[[35,245],[155,245]],"name":"candidate-menu"}
{"tap":[72,130],"name":"candidate-keep"}
```

持按取帧可使用分段 touch，最后必须释放。原生有识别阈值，不要求每个模拟指针样本都产生同等像素位移：

```json
{"touch":[96,360,1],"settleMs":50,"name":"candidate-down"}
{"touch":[96,350,1],"settleMs":40,"name":"candidate-start"}
{"touch":[96,240,1],"settleMs":40,"name":"candidate-held"}
{"touch":[96,240,0],"settleMs":300,"name":"candidate-released"}
```

## 安装核对

- [ ] 用户任务范围包含部署，且包已完成应有检查。
- [ ] AstroBox 只有一个连接目标，核对“小米手环9 NFC版”、型号 M2346B1、固件和当前应用版本。
- [ ] 队列没有旧的未完成安装，签名身份未换。
- [ ] 执行 `npm run device:install` **一次**。
- [ ] CLI 超时也先查队列；100% 或空队列都不足以证明安装完成。
- [ ] 重新进入设备 → 快应用，核对 `com.jiyehoo.banddesk` 的新 versionCode。
- [ ] 记录 RPK 文件、大小、SHA-256、实际安装版本以及是否仍待用户验收。
- [ ] 若包含连接功能，分别记录 macOS App 版本、插件版本、插件导入状态、首个快照 revision 和同 revision ACK。

不访问带 AuthKey 的设备信息接口来输出整段 JSON；不得操作 ADB 实体手机、解绑／恢复出厂或 NFC／支付。连接问题见 [部署边界](device-setup.md)。

## 真机反馈

按本轮变更要求反馈：滑动开始是否及时、持按是否移动、短拖回弹、连续切屏、按钮状态更新、弧边可读性、持续黑线／残影。需要时记录页面、动作顺序、版本和出现时刻，区分“一次看到正常”和“多次操作确认”。

长期常亮另做计时：30 分钟／2 小时、hide/show、到期和退出后的息屏、重新放入底座、充电覆盖。真实功耗需要测量条件和对照；没有数据不作“省电了多少”的结论。
