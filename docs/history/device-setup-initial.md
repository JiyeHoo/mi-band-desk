# 首次连接与实机验证

目标：小米手环 9 NFC / OS 3.1.32。原绑定手机为另一台 Android，无需接入 ADB。

当前进度（2026-09-20）：用户已完成 Mac AstroBox 连接，“桌面时钟”已更新到 0.1.3，
设备快应用列表已核对 `com.jiyehoo.banddesk` / 版本号 4。无需重新执行首次连接。
本轮修改启动器图标和可见名称，待用户重新进入应用列表确认大小、名称与启动。
0.1.1 后续反馈为刚打开即无法点击；0.1.2 已修改输入坐标、返回拦截和胶囊布局。
用户已确认本轮交互和弧边布局都正常；下一步做常亮及桌搭观察。最新结果以 `handoff.md` 为准。

## 首次连接

1. Mac 上的 AstroBox 已复制自项目官方 v2.1.0 ARM 安装包。
   该发布包标注 unsigned；初次 `spctl` 校验未通过，后续由用户手动完成启动与连接。
   在新环境中如有系统拦截，记录提示后再处理。不要关闭全局系统安全策略。
2. 正常进入后，允许蓝牙权限，在设备列表里导入绑定手环的同一个小米账号。
   账号密码和二次验证由用户输入，不需要提供给 Codex。
3. 在原绑定手机的小米运动健康中先同步一次已有数据。
4. 退出手环桌搭模式，在手环设置/系统操作中找到“连接新手机”。
   按 AstroBox 官方教程进入待连接状态，再在 Mac 中选择手环并在手环上确认。
   这会影响原手机连接；无需在原 App 中删除设备，也不要选择恢复出厂。
   如固件提示清除数据，停在该提示处确认其具体内容。
5. 如果原手机抢先回连，可临时关闭原绑定手机的蓝牙再连接 Mac。
6. AstroBox 显示已连接，核对型号和 OS，然后运行 `npm run device:status`。

## 安装与第一轮观察

1. 安装前让手环处于正常模式；执行 `npm run device:install`。
2. 从手环应用列表打开“桌面时钟”。
3. 先不滑动，点击“更多”验证按钮；用菜单的“翻转”调整方向。
   在两种方向下分别上下左右滑动，画布应保持原位；上滑打开菜单，下滑返回时钟。
   系统返回应只打开菜单，不直接退出；滑动后再点击仍应响应。文字和按钮不得被弧形边缘裁切。
4. 点击“常亮：关”切到 30 分钟；状态应显示“常亮已申请”。
5. 放入桌搭并供电，观察是否被充电界面或原生桌搭模式覆盖。
6. 至少观察 5 分钟，再完成 30 分钟测试；记录退出、通知、息屏等行为。
7. 点击时间查看前台进入次数。进后台又恢复后，累计前台时长不应包含隐藏时间。
8. “更多 → 退出 → 确认退出”应回到系统，正常自动息屏应恢复；“继续显示”应取消退出。

建议反馈：安装结果、画面是否完整、按钮是否准确响应、常亮实际时长、插入底座后的变化。

首次安装中，CLI 在 10 秒时提示超时，而任务随后正常完成。遇到相同情况，
先查看队列，再在设备信息 → 快应用列表核对包名，勿直接重复安装。
