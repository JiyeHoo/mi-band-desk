# 0.5.1：原生切页、日历底栏、设置刷新

2026-09-20。目标 Band 9 NFC / M2346B1 / OS 3.1.32 / 192×490。

## 用户反馈与证据边界

0.5.0 真机未通过：滑动不跟手，松手后约一秒才开始切页且卡顿；班／休位置不合理；设置按钮点击时放大闪烁、轮廓不完整。此前模拟器通过不等于真机通过。0.4.1 黑线修复已有用户确认，本轮不恢复任何原生旋转父层。

代码确认的成本：首次 move 创建目标卡片和字形数组；每个 move/定时帧通过响应式样式重新写两个整屏容器的位置；keep 的 pending 和结果会重建菜单图片数组、替换整卡。`object-fit:fill` 不在 Vela image 支持列表中。这些是修复依据，不能单凭代码给出真实设备一秒延迟的各项耗时或固件内部根因。

## 实现

- 使用原生 swiper 处理拖动、惯性／回弹和分页。桌面列表物理纵向，外层设置／桌面物理横向，默认横屏观看时正好对应左右／上下。保留根 scroll 双轴关闭；不再覆盖阻断手势的全屏独立输入层。
- 三个桌面和设置常驻，时间／日期变化才更新图片数组。触摸开始立即暂停眼睛属性更新；移动回调仅做防误触，**不写卡片位置，也不创建页面**。配置原生 duration=160；该值不是实测设备响应时长。
- 通过 change 同步索引，swipestart/end 暂停／恢复眼睛；缺失结束事件有有界恢复。单元测试只验证 JS 同步和资源清理，原生拖动必须用原生渲染验证。删除旧 JS 转场控制和重复 swipe 后备导航，避免与原生滚动互相竞争。
- 日历星期行只显示星期；下方优先节日名，否则显示休／班。同一连续官方休假区间以相连薄荷绿底条表示；调休上班为珊瑚色。无标记的普通周末不冒充官方假期，跨当前七天视图在边界封口。
- 设置两张卡片的底色、描边、标签合并为一张固定 192×490 图片，轮廓向卡片内侧留 2px 绘制空间。只替换内部 40×160 物理像素状态图，尺寸由 layout.js 统一生成，使用文档支持的 object-fit:none。快速 pending → 结果跳过中间图；超过 120ms 才显示“申请中”，失败正常显示。
- 不改常亮权限和到期／hide／exit 释放；仅显式两步确认退出应用。26 个表情及手势保留。

## 官方依据

- [swiper](https://iot.mi.com/vela/quickapp/zh/components/container/swiper.html)：原生拖动、纵向、索引、duration；开始／结束事件 API 2+，本项目最低 API 为 2。
- [通用事件](https://iot.mi.com/vela/quickapp/zh/components/general/events.html)：touch 坐标及冒泡。
- [image](https://iot.mi.com/vela/quickapp/zh/components/basic/image.html)：none / contain / cover / scale-down；不使用未列出的 fill。
- [性能建议](https://iot.mi.com/vela/quickapp/zh/guide/best-practice/business.html)：减少动态样式、嵌套和回流；保持图片与显示尺寸一致。

当前官方文档没有将上述基础 swiper 属性排除在 Band 9 外；PRE 4.0 已验证嵌套滑动，实际 3.1.32 的流畅度仍以用户真机反馈为准。

验证结果及最终安装状态见 validation.md 与 handoff.md。模拟器的常亮模块不可用；成功状态的原生图像检查采用独立模拟器探针，不将它当成真机 API 或省电验证，探针不安装到手环。
